# 证据链、置信度与合规边界

## 1. 证据链格式

每条结论都必须能回溯到原始数据。最小证据单元：

```
[信号] S3 同题共现
[事实] 账号A 于 2026-08-05、账号B 于 2026-09-05 分别回答「知乎交易圈子水平比较高的用户有谁？」
[来源] https://www.zhihu.com/answer/<id>（采集于 2026-10-07T04:40Z）
[推断] 两账号在同一批「荐号类」问题上错峰覆盖，非偶然撞车
[反例检查] 该问题下有 300+ 回答，两账号分属不同时间窗，排除「同时被热榜推送」
```

四要素：**信号 → 事实 → 来源 → 推断**，外加**反例检查**。
没有来源链接的结论不得写入报告。

## 2. 置信度分级

| 级别 | 条件 | 措辞建议 |
| --- | --- | --- |
| 高 | ≥3 个高权重信号族 + ≥1 个中权重族 | 「高度疑似协同推广行为」 |
| 中 | 2 个高权重族，或 1 高 + 2 中 | 「存在协同迹象，需进一步核实」 |
| 低 | 仅弱信号 | 「未发现充分证据」 |

**禁止措辞**：

- ❌「就是水军」「证实是同一人」「确定刷赞」
- ✅「表现出协同行为特征」「无法判定动机」「疑似」

置信度是**对行为模式的判断**，不是**对动机的判断**。两者必须分开表述。

## 3. 报告模板

```markdown
## 一、结论            置信度 + 一句话 + 明确写出「不能证明动机」
## 二、信号命中表      信号 / 权重 / 是否命中 / 说明
## 三、数据摘要        目标画像 + 提及者表
## 四、关键证据        按信号族分节，每条附日期与原始内容
## 五、误报排除        逐条勾选
## 六、无法判定的部分  动机 / 同一人 / 点赞 / 采样偏差（不可删除）
## 七、采集局限        参数、上限、遗漏范围
```

第六、七节是**强制项**。删掉它们，报告就从「研判」退化成「指控」。

## 4. 匿名化

对外发布必须匿名化：

```bash
node scripts/analyze.mjs evidence.json --anonymize --out report.md
```

处理方式：

- 目标账号 → `目标账号`；提及者 → `推广号A/B/C`；其他出现者 → `账号NN`
- url_token → SHA-256 前 10 位
- **正文级脱敏**：评论内容里出现的昵称也会被替换

匿名化后仍建议人工通读一遍：正文里可能残留未被采集到的第三方姓名。

## 5. 合规与伦理边界

### 允许

- 采集与分析**公开**页面
- 平台治理、舆情研判、投资尽调、学术研究
- 内部研判报告与人工复核

### 禁止

- 骚扰、人肉、私信轰炸
- **公开点名指控**真实账号
- 把工具输出直接作为处罚、封号、对外披露的依据
- 绕过登录、破解接口、批量注册账号

### 法律提示

- 基于间接证据公开点名，在多数法域下可能构成**名誉权侵权**或不正当竞争
- 涉及个人信息处理时遵守当地法律（如中国《个人信息保护法》），自动化决策应保留人工复核
- 使用者需自行确认符合目标平台的用户协议与 robots 规则

## 6. 数据保留

- `evidence.json` 含账号标识与评论正文，属个人信息载体，**不要提交到版本库**（仓库 `.gitignore` 已默认忽略）
- 研判结束后按需删除原始数据
- 分享结论时优先分享**匿名化报告**，而非证据包
