# 检测方法论

## 0. 前提：为什么只能给「疑似度」

CIB 检测的黄金证据是**行为日志**（谁在什么时间对什么内容做了什么操作）。
知乎只公开**聚合结果**，不公开**操作者身份**：

| 想要的证据 | 能否拿到 |
| --- | --- |
| 谁点了赞 | ❌ 平台不公开 |
| 谁在什么时候点了赞 | ❌ |
| 评论者身份与内容 | ✅ |
| 关注关系 | ✅ |
| 发帖时间 | ✅ |
| 私信、资金往来 | ❌ |

所以：**能证明「协同」，不能证明「同一个人」或「收钱」**。报告必须写清这条边界。

## 1. 证据包结构（`evidence.json`）

```jsonc
{
  "meta":     { "generated_at", "target_input", "notes": [] },
  "target":   { "profile": {...}, "activity": [...], "followees": [...], "followers_sample": [...] },
  "mentions": { "query", "fetched", "items": [...], "by_author": [...] },
  "promoters":[ { "author", "token", "mention_count", "mention_votes",
                  "profile", "followees", "activity", "posts" } ],
  "comments": [ { "post_url", "post_title", "post_author", "totals", "fetched", "items": [...] } ]
}
```

## 2. 信号定义

### S1 · 内容半径塌缩（权重：高）

对每个高频提及者，计算其动态里「推荐类」内容占比。

```
radius = 推荐类动态数 / 总动态数
推荐类关键词 = 关注|推荐|高手|大V|大神|水平|值得|技术|博主|排名|谁
```

**强模式**：老账号长期沉默（数年无动态）→ 某日起内容半径突然塌缩到推荐类。
这是养号/买号转推荐号的标志。

判读：`radius > 0.6` 且近期集中 → 命中。

### S2 · 提及集中度（权重：高）

对 `mentions.by_author` 排序，看 Top N 是否贡献了大部分提及。

```
concentration = top3 提及数 / 全部提及数
```

同时**横向对比**：如果推荐名单里有多个账号，分别统计各自被提及次数。
被提及最多的那个才是真正目标；粉丝量大、bio 明确不变现的账号通常是**信用锚**。

### S3 · 同题共现（权重：高）

多个账号是否反复回答**同一批问题**。计算两两之间的共同问题数。

**错峰**（A 在 8 月发、B 在 9 月发同一问题）比同日更能说明是**接力占位**而非偶然撞车。

### S4 · 评论区闭环（权重：高）

三条子信号：

1. **目标本人出现在推荐自己的帖子评论区** ← 最强
2. 目标与推荐者以**熟人语气**互动（玩笑、昵称、内部梗）
3. 帖子作者**自我回复占比高**（维持评论区活跃）

另外统计模板化捧场语命中：`良心推荐` / `已关注` / `支持` / `感谢` / `学到了`。

### S5 · 关注关系（权重：中）

- 推荐者是否关注目标
- 推荐者之间是否关注（**单向**说明存在主从）
- 目标是否回关（不回关 = 目标处于被服务位置）

### S6 · 时间爆发（权重：中）

- 同一账号**单日多帖**，且都是同类问题
- 多账号在短窗口内集中发帖

⚠️ 热点事件会造成自然聚集。必须叠加「立场一致 + 账号低权重 + 指向同一目标」才能定性。

### S7 · 话术模板（权重：中）

推荐名单与句式高度重复。抽取重复出现的账号名组合与固定短语。

模板越稳定、跨问题越一致，越不像自发表达。

### S8 · IP 同地（权重：低）

只作辅助。省份人口越多，巧合概率越高，**单独不构成证据**。

### S0 · 分散度闸门（前置条件，必须先过）

协同推广的**前提**是「少数账号垄断提及」。所以先算两个数：

@@BT@@@@BT@@@@BT@@
concentration   = Top3 提及数 / 全部提及数
singleMentionR  = 只提及 1 次的账号数 / 提及账号总数
@@BT@@@@BT@@@@BT@@

若 @@BT@@concentration < 0.3@@BT@@ 且 @@BT@@提及账号 ≥ 10@@BT@@ 且 @@BT@@singleMentionR > 0.6@@BT@@，
判为**社区自然讨论**，**置信度上限直接压到「低」**。

理由：在垂直领域（如知乎投资圈），活跃用户天然会在同一批问题下反复出现。
**同题共现（S3）与时间爆发（S6）会自然发生**，不能作为协同证据。
先过这道闸门，再谈后面的信号族。

> 反例（真实）：某目标 151 条提及分散在 129 个账号上，117 个只提 1 次，Top3 仅占 11%。
> 此时 S3、S4、S6 仍然命中，但那是社区讨论的副产品，不是协同。

## 3. 打分与置信度

不要用单一阈值。按信号族命中数分级：

| 置信度 | 条件 |
| --- | --- |
| **高** | ≥3 个高权重族 + ≥1 个中权重族 |
| **中** | 2 个高权重族，或 1 高 + 2 中 |
| **低** | 仅弱信号（时间/IP/互关） |

**永远不要输出 100%。** 并强制附上「无法判定的部分」。

## 4. 报告结构

```
## 结论            一句话 + 置信度
## 证据链          按信号族分节，每条附原始链接与时间戳
## 数据摘要        账号表、时间线、共现矩阵
## 无法判定的部分  明确列出（动机、同一人、资金）
## 局限与偏差      搜索上限、采样范围、平台不公开项
```

## 5. 误报清单（必须逐条排除）

| 误报 | 特征 | 如何排除 |
| --- | --- | --- |
| 热点涌入 | 大 V 爆款引来自然发帖潮 | 看是否立场一致 + 账号低权重 + 指向同一目标 |
| 正常互推 | 同领域 KOL 互相推荐 | 看是否只围绕单一目标、有无闭环互动 |
| 粉丝自发安利 | 真实粉丝推荐喜欢的博主 | 看账号内容半径是否塌缩、是否有跨账号协同 |
| 合法机构矩阵 | 券商/基金官方矩阵号 | 用 `is_org` / 认证字段区分 |
| 搜索偏差 | 提及次数只是近似值 | 报告中注明上限与排序方式 |
| 同名不同人 | 中文名重名 | 用 `zhihu_profile` 的候选列表核对 url_token |
